1. Authentication Lifecycle & Security Gate

The management portal enforces a zero-trust entry gate. Any unauthenticated access to /admin/* (excluding /admin/login and /admin/forgot-password) triggers an immediate HTTP 302 redirection to the login challenge.

Login Form Security Directives

  • No Auto-Saved Credentials: The input fields load with autocomplete="off" and completely blank values. Browser credential auto-fill is prevented to safeguard shared operatory workstations.
  • Brute-Force Rate Limiting: In Laravel native mode, the throttle:5,1 middleware blocks IP addresses after 5 failed login attempts for 60 seconds.
  • Password Hashing: Passwords in the MySQL users table are hashed via bcrypt (12 rounds) or Argon2id.

Login HTTP Transactions

Route: POST /admin/login

Headers: Content-Type: application/x-www-form-urlencoded or application/json

Payload:

{
  "email": "dr.caldwell@example.com",
  "password": "Doctor@DemoPass2026!",
  "remember": "1"
}

Success Response: HTTP 302 Found → Location: /admin/dashboard with encrypted session cookie PHPSESSID.

Failure Response: HTTP 302 Found → Location: /admin/login?error=invalid_credentials

2. RBAC Permission Engine & Zero Data-Leak

Permission enforcement is executed at the earliest stage of request dispatch in StandaloneRunner::checkPermission() and Laravel route middleware. If a user attempts to access an unpermitted route, execution halts immediately: 

public static function checkPermission(string $module, string $role): bool
{
    if ($role === 'super_admin' || $role === 'admin') {
        return true;
    }

    $matrix = [
        'doctor' => ['dashboard', 'calendar', 'odontogram', 'patients', 'inventory'],
        'receptionist' => ['dashboard', 'calendar', 'patients'],
        'website_manager' => ['dashboard', 'theme-customizer', 'seo-manager', 'seo-redirects', 'cms-pages'],
        'billing' => ['dashboard', 'calendar', 'patients', 'inventory', 'billing'],
    ];

    return in_array($module, $matrix[$role] ?? [], true);
}
Zero Clinical / Financial Leak Guarantee: When a Receptionist visits /admin/emr/odontogram or a Doctor visits /admin/billing, the server returns HTTP 403 Forbidden via renderForbidden(). The requested view is never loaded into memory, ensuring zero HTML fragments or patient records are leaked to unauthorized roles.

3. Session & Cookie Security Lifecycle

Administrative sessions are governed by strict cookie flags to prevent XSS session theft and MITM interception:

Security Flag Value Purpose
httponly true Blocks JavaScript document.cookie access to defend against XSS session hijacking.
samesite Lax / Strict Mitigates Cross-Site Request Forgery (CSRF) across third-party site navigations.
secure true (Production) Ensures session cookies are transmitted exclusively over encrypted HTTPS connections.
lifetime 1800 seconds (30 mins) Automatically invalidates abandoned operatory workstation sessions.

5. Support Tickets & Root Cause Analysis (RCA)

TICKET-AUTH-101 • User redirected to login immediately after signing in
High Priority

Symptom: Doctor enters valid email and password, clicks "Sign In", but browser redirects immediately back to /admin/login.

Root Cause: PHP session save path on shared host (e.g. /tmp or storage/framework/sessions) is not writable, or domain mismatch between www.demo.com and demo.com dropped the session cookie.

Resolution Runbook:

  1. Inspect PHP session directory permissions: chmod 775 backend/storage/framework/sessions.
  2. Check .htaccess rule 1: Ensure HTTPS canonicalization forces uniform host (e.g. RewriteCond %{HTTP_HOST} ...).
  3. Verify session.cookie_domain in php.ini or StandaloneRunner.php does not pin an invalid subdomain.
TICKET-AUTH-102 • Receptionist sees "403 Forbidden" when opening Patient Billing profile
Configuration

Symptom: Front desk receptionist Emily cannot access /admin/billing to collect cash copay from patient.

Root Cause: By security design, role receptionist does not have billing in $matrix['receptionist']. Front desk payments must be tendered under role billing (Robert Fox) or clinic admin.

Resolution Runbook:

  1. If clinic policy permits receptionists to collect POS payments, add 'billing' to $matrix['receptionist'] in StandaloneRunner.php (line 119) and update backend/app/Enums/UserRole.php.
  2. Otherwise, train staff to use the dedicated Billing Officer terminal or escalate to the Clinic Manager.
TICKET-AUTH-103 • CSRF Token Mismatch (HTTP 419) on Login Form
Session Timeout

Symptom: Staff leaves login tab open overnight; clicking Sign In in the morning triggers Laravel 419 Page Expired.

Root Cause: The CSRF token embedded in the hidden _token input expired because the session reached its 30-minute timeout.

Resolution Runbook:

  1. In login.blade.php, ensure the page handles 419 gracefully by reloading the login view when a token expires.
  2. In StandaloneRunner.php, fallback token generator automatically re-arms the session token if expired on GET requests.
